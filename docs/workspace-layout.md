# 工作区格式

用户选中的任意文件夹就是一个项目。应用扫描其中的图片，但不会接管用户对多级目录的分类方式。

```text
MyDataset/
├─ group-a/
│  ├─ image-001.webp
│  ├─ image-001.txt
│  ├─ image-001.zh-CN.txt
│  └─ image-001.json
├─ group-b/
│  └─ image-002.png
└─ .annotation-workspace/
   ├─ project.json
   ├─ state.sqlite3
   ├─ thumbnails/
   ├─ history/
   ├─ validation/
   ├─ runs/
   ├─ recovery/
   ├─ cache/
   └─ logs/
```

## 用户可见文件

- 图片是当前工作版本，界面默认只展示它。
- 同名 `.txt` 是唯一活动标注。内容可能是 XML 或任何其他纯文本结构，应用不提取固定字段，也不清洗模型响应。
- `图片名.语言代码.txt` 是对应标注的只读译文旁车，例如 `image-001.zh-CN.txt`。每个语言可独立存在；译文任务永远不会覆盖活动标注。
- 同名 `.json` 是可选元数据。项目设置保存要拼入 User Prompt 的键名；缺文件或缺字段不会阻止任务。

批量标注发现同名 `.txt` 时一律跳过，即使文件为空或未通过校验。异常状态会留给人工检查，避免自动覆盖已有工作。

标注任务既可以使用 LLM 模型连接，也可以使用设置页中的本地 Tagger 配置。本地模型权重属于全局受管资源，
不会复制到数据集目录；项目数据库只保存任务创建时的模型安装 ID、内容指纹、阈值、类别、设备和并发快照。
因此移动项目不会携带数 GB 权重；尚未完成的本地任务仍绑定原安装，换机后应先导入模型并重新创建任务。

批量翻译只读取活动标注，并可选择全局翻译 Prompt 预设，以及跳过已有译文、补齐缺失且重译过期项，或覆盖所选范围。任务会保存 Prompt 的模板与目标语言展开结果，之后修改预设不会影响已经创建的任务。数据库记录生成译文时的源标注哈希；源 `.txt` 改动后，界面会把旧译文标记为过期。模型输出必须保留原文的标签、属性和顺序，写入前还会再次确认源版本未变化。

## 内部目录

- `project.json`：稳定项目 ID、名称和项目级 Prompt / 扫描设置。
- `state.sqlite3`：图片索引、标注/翻译与导出任务、请求尝试、校验和预处理记录。
- `runs/`：每次远端请求或本地 Tagger 推理的脱敏成功/失败产物。
- `recovery/`：预处理前的原文件，默认永久保留。
- `history/` 与数据库修订表：手工保存、生成保存和删除前快照。
- `thumbnails/`、`cache/`：可重建派生数据。

整个目录移动后，`project.json` 中的稳定 ID 不变。再次选择新路径时，全局“最近项目”记录会更新到新位置。

## 导出目录

导出目录不属于项目内部结构。用户通过桌面原生目录选择器指定一个已经存在的空文件夹，该文件夹就是最终输出位置；应用不会再创建数据集名称或任务 ID 子目录。源项目中的多级路径会被展平，目录中只放原始图片字节和导出时存在的活动同名 `.txt`，不会写入 `state.sqlite3`、清单、日志或恢复文件。

展平后任何图片或预期 `.txt` 文件名发生大小写不敏感冲突时，必须重新整理范围或文件名后才能导出。缺少、为空、结构异常或编码异常的标注会在导出前警告；用户明确强制导出时，缺少标注的条目只复制图片，其余 `.txt` 保留原始字节。

## 数据安全约束

预处理先复制原文件到本项目恢复区。需要缩放或转换的图片由有界线程池写入操作私有的 `staging/`，随后协调器按预览顺序原子提交；临时 staging 会在成功或失败后清理。批量重命名保留图片所在目录，并同步迁移活动标注、全部语言译文与同名 `.json`；纯重命名不会重新编码图片。数据库更新失败时立即恢复正在处理的文件；批次中途失败时逆序恢复已经完成的条目。撤销前会核对当前图片哈希，若用户在预处理后手动修改过图片，应用会拒绝覆盖该修改；重命名后的标注、译文或元数据改动会随撤销迁回原文件名。
