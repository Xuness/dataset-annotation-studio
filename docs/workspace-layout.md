# 工作区格式

用户选中的任意文件夹就是一个项目。应用扫描其中的图片，但不会接管用户对多级目录的分类方式。

```text
MyDataset/
├─ group-a/
│  ├─ image-001.webp
│  ├─ image-001.txt
│  └─ image-001.json
├─ group-b/
│  └─ image-002.png
└─ .annotation-workspace/
   ├─ project.json
   ├─ state.sqlite3
   ├─ thumbnails/
   ├─ history/
   ├─ validation/
   ├─ runs/
   ├─ recovery/
   ├─ cache/
   └─ logs/
```

## 用户可见文件

- 图片是当前工作版本，界面默认只展示它。
- 同名 `.txt` 是唯一活动标注。内容可能是 XML 或任何其他纯文本结构，应用不提取固定字段，也不清洗模型响应。
- 同名 `.json` 是可选元数据。项目设置保存要拼入 User Prompt 的键名；缺文件或缺字段不会阻止任务。

批量标注发现同名 `.txt` 时一律跳过，即使文件为空或未通过校验。异常状态会留给人工检查，避免自动覆盖已有工作。

## 内部目录

- `project.json`：稳定项目 ID、名称和项目级 Prompt / 扫描设置。
- `state.sqlite3`：图片索引、任务、请求尝试、校验和预处理记录。
- `runs/`：每次模型请求的原始成功或失败响应。
- `recovery/`：预处理前的原文件，默认永久保留。
- `history/` 与数据库修订表：手工保存、生成保存和删除前快照。
- `thumbnails/`、`cache/`：可重建派生数据。

整个目录移动后，`project.json` 中的稳定 ID 不变。再次选择新路径时，全局“最近项目”记录会更新到新位置。

## 数据安全约束

预处理先复制原文件到本项目恢复区，再通过同目录临时文件原子替换。数据库更新失败时立即恢复正在处理的文件；批次中途失败时逆序恢复已经完成的条目。撤销前会核对当前文件哈希，若用户在预处理后手动修改过文件，应用会拒绝覆盖该修改。
