# 工作区格式

用户选中的任意可写文件夹就是一个项目。应用直接索引其中的图片，不复制图片，也不接管用户原有的多级目录分类。

```text
MyDataset/
├─ group-a/
│  ├─ image-001.webp
│  ├─ image-001.txt          # 可选：迁移前已有的旧标注
│  └─ image-001.json         # 可选：Prompt 元数据
├─ group-b/
│  └─ image-002.png
└─ .annotation-workspace/
   ├─ project.json
   ├─ state.sqlite3
   ├─ thumbnails/
   ├─ history/
   ├─ validation/
   ├─ runs/
   ├─ recovery/
   ├─ cache/
   └─ logs/
```

## 标注的真实来源

`state.sqlite3` 是标注的唯一活动来源。Tagger、LLM、人工编辑和翻译都只创建数据库修订，运行过程中不再写图片旁的
TXT。图片旁的旧文件有以下边界：

- 首次升级到数据库标注存储时，同名 `.txt` 导入“原有标注”通道；`图片名.语言代码.txt` 导入对应翻译通道。
- 导入内容被记录为迁移时确实存在，但应用不猜测它是 Tags、描述还是其它自定义文本。
- 迁移前先把项目 SQLite 备份到 `history/pre-annotation-store-v2-*.sqlite3`。
- 导入成功后旧文件原样保留，不自动删除；之后在外部修改它不会反向覆盖数据库。
- 同名 `.json` 仍是只读 Prompt 元数据，不属于标注存储。

因此，数据库迁移完成后的 TXT 只可能是旧输入或用户明确导出的产物，不是旁路写入接口。

## 标注通道、可用性与人工复核

每张图片可以同时拥有多个独立通道：

| 通道 | 内容 | 典型写入方 |
| --- | --- | --- |
| 原有标注 `existing_annotation` | 不推断语义的纯文本 | 旧 TXT 导入、人工修订 |
| Tags `tags` | 有顺序的结构化 Tag；可带类别、置信度和来源 | 本地 Tagger、人工增删 |
| LLM 描述 `description` | 模型原始文本 | 多模态模型、人工修订 |
| 翻译 `translation:<language>` | 每种语言独立的纯文本 | 翻译任务、人工修订 |

每个通道保存不可变修订，并分别维护：

- `head_revision_id`：编辑器当前看到的版本；
- `reviewed_revision_id`：用户最近一次明确人工复核的版本，仅作为质量管理标记；
- 生成时对应的图片内容哈希；
- 来源任务、输入修订和生成参数元数据。

当前 head 只要校验通过、不是墓碑且绑定当前图片，就处于“当前可用”状态，无需先人工复核即可参与翻译、
Tag 辅助、统计和默认导出。人工复核与可用性相互独立：复核不会替代校验，也不会把无效内容变成有效内容。
Tagger、LLM、翻译结果和新导入的旧 TXT 默认尚未复核，但通过校验后立即可用。

图片内容变化后，原修订显示为“已过期”。用户可以在单图编辑器复核，也可以在素材列表打开批量操作页，按
Tags、LLM 描述、原有标注或具体译文语言选择要复核的类别；对过期版本执行复核会为当前图片创建新修订，而不是
改写旧历史。批量删除使用同一套数据库范围预览，只列出所选图片中实际存在的类别，并只为勾选通道写入墓碑修订，
历史内容仍可查看和恢复到编辑器。“原有标注”页签默认隐藏，仅在当前素材确实存在导入内容时显示。

## Tagger 辅助 LLM

Tagger 始终写入独立的 Tags 通道。“使用 Tags 辅助 LLM”是素材页“提示词”区域中的项目设置，
与 System Prompt 和 User Prompt 一起保存：

1. 任务创建事务逐图冻结当时通过校验且匹配当前图片的 Tags `head_revision_id`；
2. Worker 读取该固定修订的 Tag 名称；
3. 在 JSON 元数据行之后追加 `tags: ["tag_a","tag_b"]` 到 User Prompt；
4. LLM 结果写入独立的 LLM 描述通道。

开关默认关闭。素材页会分别展示 Tags 追加状态、准确的追加行以及最终 User Prompt；没有可用 Tags 的图片仍正常执行，
只是不追加辅助行。任务创建后继续编辑或复核 Tags，不会改变该任务已经冻结的输入。

## 内部目录

- `project.json`：稳定项目 ID、名称和项目级 Prompt / 扫描设置。
- `state.sqlite3`：图片索引、标注文档与修订、结构化 Tags、修订依赖、任务、请求尝试、导出与预处理记录。
- `runs/`：远端请求或本地 Tagger 推理的脱敏成功/失败产物；不保存图片副本。
- `history/`：迁移前数据库备份等长期历史文件。
- `recovery/`：预处理前的原文件，以及可撤销的素材文件包。
- `thumbnails/`、`cache/`、`validation/`：可重建派生数据。

整个目录移动后，`project.json` 中的稳定 ID 不变。再次选择新路径时，全局“最近项目”记录会更新到新位置。最近路径身份遵循当前操作系统：Windows 忽略大小写，Linux 保留大小写。

## 导出目录

导出目录不属于项目内部结构。用户选择一个已经存在的空文件夹；预览会冻结图片哈希、所选通道的具体 revision ID
以及最终内容，Worker 只物化该快照。

单通道 TXT 仍提供常见的扁平训练集：

```text
Export/
├─ image-001.webp
└─ image-001.txt
```

同时选择多个 TXT 通道时，每个通道成为独立训练集变体，避免把不同语义强行合并：

```text
Export/
├─ tags/
│  ├─ image-001.webp
│  └─ image-001.txt
├─ description/
│  ├─ image-001.webp
│  └─ image-001.txt
└─ translation-zh-CN/
   ├─ image-001.webp
   └─ image-001.txt
```

JSON 可以单独选择，也可以与 TXT 同时选择。逐图 `*.annotations.json` 会保留所有所选通道、修订 ID、可用状态、
人工复核状态、校验状态和结构化 Tag 字段；多通道 TXT 同时启用时，JSON 放在 `metadata/`。

默认导出当前可用的 head；用户也可以显式限制为已人工复核版本。尚未复核本身不产生导出警告，过期、缺失或
校验异常仍会在预览中提示。目标目录非空、
图片变化、路径越界和最终目标名称冲突属于不可绕过错误。继续已停止任务前会校验已经写出的文件，绝不覆盖用户后来修改的内容。

## 数据安全约束

标注修订是 SQLite 事务，不与 TXT 双写。输出资源租约以“素材 ID + 通道 + 语言”为键，防止编辑器、Tagger、LLM
或翻译任务同时覆盖同一通道；不同通道可以独立工作。

预处理和素材删除仍可能处理图片旁的旧 TXT、旧译文和同名 JSON，因为这些文件是用户数据集中的普通伴随文件。此类文件操作继续遵循
“预览计划 → 私有 staging / recovery → 顺序提交 → 失败补偿”，但不会把外部 TXT 重新认定为活动标注。
